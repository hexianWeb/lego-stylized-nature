# 给新 Agent 的工作流：Blender 低模地标制作与游戏接入

适用项目：`D:\workplace\lego-stylized-nature`。

目标：制作有辨识度、可编辑的 LEGO 风格低模建筑，交付 Blender 源文件与 GLB，再把同一个模型接入真实 biome 地形，完成摆放、入场、预加载与验证。以已经完成的沙漠日轮门为参考。

## 1. 先确认任务所在阶段

| 用户已有内容 | 从哪里开始 |
| --- | --- |
| 只有建筑想法 | 概念与轮廓设计 |
| 已认可概念图 | Blender 建模 |
| 已认可 Blender 模型 | 导出与资产检查 |
| 已提供或修复并导入 GLB | 直接检查项目中的 GLB，进入游戏接入 |

用户最近的选择是 **Blender 直接建模**。先前尝试过程序化拼砌建筑和 Tripo；前者视觉与维护成本不理想，后者生成模型过大。除非用户重新指定，不自动切回这些方案。

用户已明确说明：**墙壁闪纹来自 Blender 模型重面，用户已修复并把 GLB 导入项目。后续 Agent 不再操作该模型或重新覆盖它。** 当前接入优先使用 `public/model/landmarks/desert-sun-gate.glb`。

`build_model.py` 只是制作基线，不代表用户修复后的最新模型。接入任务中不得为“同步资产”而运行它，再把导出物复制覆盖用户 GLB。若源文件与发布文件不同，先记录差异；确实需要知道哪个版本才可继续时，再询问用户，其他工作照常推进。

## 2. 开始工作前

1. 阅读仓库 `AGENTS.md`，查看 `git status`，识别用户已修改、已暂存和未跟踪的内容；不要整批重置或暂存。
2. 检查 `.codegraph/`。存在时，理解或定位代码先用 `codegraph_explore`；没覆盖到的文件或明确过期的结果，再直接读取。不存在则跳过，不自行索引。
3. 阅读当前 `WorldConfig` 和渲染实现。仓库旧说明可能滞后，不能按旧笔记假定后处理关闭或使用旧 Three API。
4. 先给用户简短进展说明，持续工作中定期报告实际发现。可并行安排美术检查、地形选址、资源预热等独立任务，并明确各自文件归属。
5. 本流程不要求创建独立聊天、提交、推送或部署；按用户实际授权执行。

## 3. 概念设计：统一风格，区分轮廓

统一规则：大块积木、轻倒角、少量凸点、哑光塑料、清晰色块。先让游戏视角下的剪影成立，再增加细节；每栋建筑约 3–5 个主色。宏大感来自比例、层次与开阔前景，不能只靠扩大占地。

| Biome | 当前建筑方向 | 最重要的轮廓特征 |
| --- | --- | --- |
| 森林 | 巨树观景居所 | 粗树干、分层树冠、嵌入房屋 |
| 秋林 | 风车粮仓 | 四片宽叶、阶梯红屋顶 |
| 沙漠 | 日轮门 | 厚重扶壁、八角通孔、青绿日徽 |
| 雪地 | 极地灯塔 | 浅色高塔、深蓝灯室 |
| 火山 | 黑岩天文台 | 深色厚基座、铜色几何穹顶 |
| 草原 | 气球远征站 | 几何球囊、宽停靠塔 |
| 湿地 | 水上驿馆 | 宽檐层顶、粗支墩 |

- 如果需要新概念图，使用可用的 imagegen 技能；先阅读其 `SKILL.md` 并告知用户。项目要使用的图片保存在工作区，记录提示词。
- 先画建筑位于对应地形中的效果，检查比例与色彩。概念图不能当作实机效果或面数承诺。
- 需要建模参考时，再生成干净背景、单栋建筑的独立视图。正、侧、背必须表达同一结构；发现矛盾就修正，不把不同造型混作一个模型。
- Blender 模型已有后，直接从同一模型渲染多个角度，得到真正一致的参考。不要再用独立生图冒充模型的准确侧视图。
- 已认可的造型不必重新生图。现有概念板和提示词见本目录其他文件。

**本阶段验收：** 缩小到游戏常见观看尺寸仍能认出建筑；支撑、入口、背面和进深合理；用户能看到具体可评审结果。

## 4. 在 Blender 中制作低模资产

### 4.1 连接与保护现场

- 先调用 Blender 的 `get_addon_status`、`get_scene_info`，了解当前文件、对象、模式、选中项和可用能力，再用 `look` 看现场。
- 通过 `execute_blender_code` 使用 bpy 建模；工具要求的 `user_prompt` 使用用户原话，不替换成 Agent 自己的子任务说明。
- 创建自己的命名集合，例如 `<Landmark>_Asset` 与 `<Landmark>_Studio`。不要清空场景，不删除用户对象，不替用户安装插件或调用付费生成器。
- 调用工具前阅读当前返回的 API 说明；枚举、渲染引擎、导出参数以实际 Blender 版本为准。查找材质节点使用节点类型，避免依赖本地化名称。

### 4.2 几何与材质

- 用少量大体块搭主轮廓，补真实厚度和必要支撑；需要贯通的门洞必须是真洞。
- 小倒角优先 1 段；凸点用低边数柱体，集中在少数能看见的顶部。先控制几何，再考虑减面。
- 优先纯色材质与少量材质槽；不要把砖缝、栏杆、凸点全部做成密集几何。
- 活动件单独建模并设正确轴心。静态建筑可以合并，保留部件顶点组方便编辑。
- 避免共面重面、隐藏重复面、法线错误和悬浮支撑。游戏内闪纹可能是重面，也可能是阴影问题；先辨别原因，不直接用偏移参数掩盖。
- 初始可把普通地标预算定在约 3k–8k 三角面，再根据造型和目标设备调整。这是设计起点，不是所有建筑的硬上限。

### 4.3 导出与度量

- 模型底部中心为原点，基础最低处在地面；应用需要的变换，记录正面与向上方向。
- 当前日轮门：Blender `+Z` 向上、`-Y` 为正面；导出 GLB 后 `+Y` 向上、`+Z` 为正面。新资产必须实际检查，不能盲套。
- 只导出建筑选中项。摄影棚地面、灯光、相机不进入 GLB；避免把整块景观地形绑定到建筑。
- 保存 `.blend`、`.glb`、真实渲染预览与资产说明。用户参与修模后，保留其最新文件，不用重建脚本覆盖。
- 度量导出后的三角面、glTF 图元、材质、贴图、字节数和包围盒。一个 Blender 网格并不等于一个绘制调用，多个材质通常会拆成多个图元。
- 若存在明显重复面，单纯“非流形边为零”不能证明资产无问题；还要看多角度渲染及实际游戏画面。

日轮门最初交付基准：5,580 三角面、4 材质/图元、无贴图、约 315 KiB；源尺寸约 `12.8 × 7.85 × 11.47`。这些是该版本的测量值，新模型或用户修复版本要重新测量。

**本阶段验收：** 正、侧、斜视角均成立；无明显穿插/闪纹；门洞或活动轴正确；源文件可编辑，导出物可独立加载。

## 5. 组织资产与代码职责

推荐目录；新建筑替换 `<asset-id>`，不覆盖日轮门：


| `src/world/prefabs/PrefabPlacer.js` | 植被与普通物件避让 |

## 6. 确定性选址与地形衔接

1. **以世界种子和区域坐标确定候选。** 不依赖区块加载顺序或当前邻居；负坐标使用正确的向下取整。当前日轮门每 3×3 chunk 区域有一个候选，不代表每个候选都接受。
2. **先按真实模型尺寸缩放，再计算旋转后的占地。** 包含基础、台阶、前后入口、植被缓冲及平台过渡带；90° 旋转需要交换长短轴。
3. **检查完整范围。** 拒绝不适合的 biome、水、岸、熔岩或过大高差。只采样中心或四角不够，范围内的小水坑也要识别。
4. **第一版把完整变形范围留在单个 chunk 内，并避开邻块 halo。** 放不下就拒绝或重新设计规模，不让边界悄悄断裂。以后确需跨块，必须让所有受影响 chunk 使用同一世界坐标规则，包括 halo。
5. **先检查原始地形，再平整。** 基础内形成平面，外圈平滑过渡，之后重新生成最终表面分类、坡度、AO 和地形实例。不能在建筑显示后才临时改地形。
6. **基座对齐真实砖顶。** 当前砖实例平移为 `height * layerHeight`，砖几何顶部另有偏移，不可直接假定为 `(height + 1) * layerHeight`。当前偏移由实际 `brickGeometry.boundingBox.max.y` 测得约 `0.12`，并传给 worker。
7. **为入口和周围植被留空。** 地形不能吞掉台阶或门洞，普通物件不能长进建筑。飞机通道按实际飞行高度和宽度做射线/包围盒检查。
8. **主线程与 worker 保持一致。** 请求传入相关 `chunks`、`landmarks` 配置；打包/解包保留 plain `terrainMap.landmarks` 描述，并对地形、放置与 AO 做一致性测试。

湿地建筑应另用水位、河床与支墩规则；火山建筑要检查稳定岩台。不要把沙漠整平方案无条件套给其他地形。

## 7. 加载、预热与资源所有权

- 小模型可以随启动资源加载并等待 ready；日轮门当前采用这种方式。后续资产增多时，再根据启动时间和内存预算改为分批预取，不能无限扩大启动必需资源表。
- 多个实例共享源几何和材质；区块回收时只更新矩阵、数量与状态，避免重复下载、解析、分配和编译。
- 日轮门使用固定区块池，每个 slot 预分配 4 个实例网格。下一种资产的网格数量、实例容量要来自实际 GLB 和场景需求，不能写死“所有模型都是 4 个”。
- **WebGPU 中临时替代网格的 compile 不等于实际对象已预热。** 当前 Three r185 有对象级 RenderObject、绑定和阴影缓存；预热真实池对象并保留其身份。
- 预热阶段临时设置可见、`count=1`、非零显现值和安全变换，执行 compile 与实际绘制。先等待主/阴影准备队列 drain，再恢复可见性、矩阵、数量、边界和显现值。
- 正常结束和异常结束都必须恢复状态；不能在队列还没结束时隐藏对象，否则任务可能被取消。
- 本项目调用预热 helper 时，`renderFrame` 需要执行渲染并等待 `Renderer.prepareVisiblePrefabs()`。这些是当前 r185 适配细节，升级 Three 后要重新检查。
- 所有权明确：Resources 负责源 GLB 几何/源材质；地标资产层负责自己创建的共享节点材质；slot 负责实例缓冲。回收一个实例不能释放仍被其他实例使用的共享资源。
- 低面数不保证不卡顿。还要检查材质、阴影、纹理上传、首次编译、原子主线程任务与同屏数量，不用一次漂亮截图替代性能验证。

## 8. 动画：保留地形逐列升起，建筑整体显现

推荐时序：

```text
资源已准备 / 区块生成
    → biome 色系大格占位消融，详细地形逐列升起
    → 建筑所依赖的地形稳定
    → GLB 整体短距上升 + 消融显现
    → 常态显示；离开回收实例，返回时复用
```

- 不把整体 GLB 交给原来的列缩放动画，否则建筑会挤压变形。若要分段升起，必须事先在模型里保留合适分组，再单独设计。
- 当前日轮门等整个 chunk 的地形动画结束后再入场：默认约 `0.55s`，上升约 `0.45` 世界单位；重播、复用和禁用地形动画时均要正常工作。
- 显现优先保持不透明深度写入，使用裁切/抖动 mask，避免大型半透明建筑的排序问题。
- **本体和阴影必须共享显现逻辑。** Three r185 的阴影覆盖材质不会自动继承普通 `opacityNode` 或 `alphaHash`；当前接入明确设置同一 `maskNode` 与 `maskShadowNode`，避免未显现的建筑先投出完整阴影。
- 灰度预览、slot 隐藏、再生成和销毁都要同步地标状态。

## 9. 验证顺序

### 自动验证

优先验证真实契约，而不是写一组只重复实现公式的测试：

- 同种子、不同访问顺序与负坐标下候选一致；无效场地拒绝。
- 基础范围平整、基座贴砖顶、过渡区域不影响邻块 halo；旋转后仍避让。
- worker 与主线程的地标、地形、放置和 AO 一致。
- 从发布 GLB 实际加载并测量包围盒，在默认飞机高度检查门洞。
- 建筑等待地形稳定、整体变换不变形；动画禁用和重播正确。
- 往返/传送后恢复同一地标，池对象数量与身份稳定。
- 预热结束或异常时状态恢复；实例销毁不误释放共享资源。

本项目使用 pnpm；需要安装依赖时执行 `pnpm install --frozen-lockfile`。现有锁文件以 `pnpm-lock.yaml` 为准。

```powershell
node --test test/sunGatePlacement.test.js test/landmarkRenderer.test.js test/landmarkPipelineWarmup.test.js test/chunkRenderSlot.test.js test/chunkColumnTransition.test.js test/chunkManager.test.js test/chunkBuildData.test.js test/natureBiomes.test.js test/voxelTerrainPlaceholder.test.js
pnpm build
git diff --check
```

上述组合在本次交付时通过 78 项测试；它不是对未来状态或整个仓库测试的永久承诺。新增测试前检查 `.gitignore`，本仓库默认忽略 `/test/*`，需要为应交付的测试增加例外。

### 实际游戏验证

1. 先进入真实世界，再查看建筑。纯模型查看器无法证明地形、阴影、区块流式加载正确。
2. 使用可用的浏览器工具检查，不绕过其交互规则。改动后刷新，读取当前页面状态与当前时间段错误；控制台可能保留上一次失败记录。
3. 检查远景到地形、地形到建筑的完整过程；环绕看基座、侧面、背面和门洞，验证暂停/恢复与入场重播。
4. 验证首次进入、回访、快速掉头/传送、禁用地形动画，以及有资源失败时的明确反馈。
5. 查看准备队列是否清空、是否失败，记录目标设备的帧时间峰值或分位数；不要只报告平均 FPS。
6. 保存真实游戏截图并在最终答复展示。留给用户的预览页保持可操作，有开始飞行、暂停和返回入口。

当前实景入口：`http://127.0.0.1:4173/dev/sun-gate.html`。需要时启动：

```powershell
pnpm dev --host 127.0.0.1 --port 4173 --strictPort
```

这是默认种子的自然有效选址，不是另造的一片展示地形。世界坐标约 `(21.66, 79.4)`；HUD 以地形格计数约为 `X108 / Z397`；chunk 为 `(1,5)`。更换种子、模型尺寸或选址参数后，需要重新找到有效站点，不能继续硬编码这个位置。

Vite root 为 `src/`，资源从 `public/` 发布。`/dev/` 子页要处理相对资源路径，例如 `<base href="/">` 配合明确的脚本地址，避免 GLB 请求落到 `/dev/model/...`，收到 HTML 后产生 JSON 解析错误。开发预览不等于生产构建已包含该 HTML 页面；生产接入由主游戏代码承担。

当前预览为便于检查高建筑，单独关闭了移轴模糊；主游戏保留自己的后处理设置。报告截图时不要把这种检查视图的差异误称为全局画面改动。

## 10. 完成交付

- 更新资产说明与运行时接入说明，标清已完成内容、尚未实现内容，以及用户后续修改的资产版本。
- 列出实际 GLB 位置、可编辑源文件位置、自然有效站点或可操作预览入口。
- 简述比例/摆放、加载与入场行为，报告实际执行的验证结果与已知限制。
- 不把“建好了模型”“模型能单独显示”和“已正确接入游戏世界”混为同一完成标准。

可给新 Agent 的任务开头示例：

```text

参照现有日轮门，为 <biome> 制作并接入 <建筑名称>。
```
