# 偶发长帧排查（2026-10-16）

## 采样方式

- Needle MCP：当前 `localhost:5173` 页面的性能报告、WebGPU timer queries、逐帧 render graph、控制台错误。
- 独立 Chrome/WebGPU 页面：1280×800 窗口，`#debug`，等待初始九区块和渲染准备队列完成；静止 1.5 秒、沿 X 轴以 8 世界单位/秒飞行 12 秒、停留 2 秒。
- 对 `ChunkManager`、植被构建、renderer 的节点构建/绑定/上传方法计时。以下 CPU 数字包含计时插桩开销，不等同于无插桩的用户体验。
- 页面帧时间来自连续帧时间戳；它与同一条记录中当前 `update()` 的耗时不是同一时间区间。

## 确认的热点与处理

### 1. 新地形和液体网格绕过异步 shader 准备

原来的渲染准备 gate 只接受 `streamingPrefab`。地形实例容量增长、首次分配水面页等情况下，新对象直接进入同步节点构建。

飞行基线中，同步 `getForRender()` 构建最高 **47.4 ms**，对应帧的主线程 `update()` 达 **84.6 ms**。该帧还执行了 13.4 ms 的区块填充、1.8 ms 的动画捕获、3.6 ms 的植被构建。

地形、水面、岩浆现在标记为 `streamingChunk`，共用现有真实 main/shadow RenderObject 的分片构建和异步 pipeline 准备。首次绘制会等准备完成，因此新网格可能延后显示。准备完成后的正常绘制和失败回退保留。

两轮修改后飞行采样均未再观测到同步 `getForRender()` 构建，准备队列无失败，浏览器无错误。

### 2. 区块与植被任务在同一帧叠加

Worker 已承担地形生成、placement 和 AO，但主线程仍负责解包、实例矩阵/颜色填充、bounds 和植被生成。

增加 `chunks.mainThreadBudgetMs`（默认 4 ms），让区块接收和植被构建共享截止时间；超时后推迟后续任务。每帧至少允许一个待处理地形任务推进；紧急中心区块已消耗预算时，不再继续填外圈。

**这不是单帧耗时硬上限**：一次 population 仍不可中断，测得区块填充仍可达 15–16 ms。植被构建也仍是原子任务。

### 3. 模糊输入 RTT 重复绘制

MCP render graph 显示相同的全分辨率 RTT 一帧写入三次：外层、水平模糊和垂直模糊。

将该内部 RTT 改为 FRAME 更新，同时固定 `updateReference` 为其自身 render target texture。后者必须同时修改：GaussianBlur 会临时替换输入 `.value`，只改 FRAME 仍会重复一次。

实测完整管线从 **8 个 pass 降为 6 个**，RTT 从 **3 次降为 1 次**；保留原有模糊分辨率与效果参数。

## 结果及仍需关注的项目

MCP 原页面 GPU 计时平均 **7.9 ms**（7.6–8.6 ms），其中 Scene 3.77 ms、Shadow Map 3.58 ms；该采样不足以解释 80 ms 以上的 CPU 长帧。

第一轮修改后，飞行 CPU 峰值为 32.3 ms，超过 33.4 ms 的间隔由基线 46/572 降到 30/630。然而最终复测仍出现 74 ms 的 CPU 长帧和 50/573 的慢帧；该长帧的同步节点构建为零。**不能据此宣称 low 帧已经全部修复，或稳定给出整体帧率提升百分比。**

下一步优先级：

1. 把单次区块实例/颜色填充与植被构建拆成可恢复的小批次，或让 Worker 返回可直接消费的实例数据。需要保证 AO、颜色顺序、动画和 bounds 一致。
2. 采集残余长帧的 CPU sampling/GC trace，区分 renderer 提交、内存回收、驱动等待和后台节点构建。现有方法计时尚不能归因最终那次 74 ms 尖峰。
3. 阴影占约半数 GPU 时间，后续可评估独立 shadow LOD；当前 GPU 采样有余量，优先处理上述 CPU 尖峰。

注意：MCP 总览 draw calls 约 2,000，但逐 pass 对象数、GPU 采样和 renderer 实际帧计数约 427–430；统计口径不一致，未把总览数字直接作为瓶颈依据。

## 验证

- 区块调度和渲染准备回归 49 项通过；相关后处理回归 6 项通过。
- 生产构建通过；WebGPU 实机飞行无控制台错误，准备队列最终清空。
- 全量测试 348 项：338 通过，10 失败。用 HEAD 的独立副本复现了这些既有失败（输入键、出生生物群系、配色、渲染配置、相机 mock 等）。
- 同时纠正了渲染准备测试误导入未安装 `vitest` 的问题，使其使用项目的 `node:test`；HEAD 基线还额外存在此测试加载失败。
